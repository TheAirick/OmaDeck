# OmaDeck v0.8.1 — Omarchy compatibility and guarded touch

This patch restores media and touch operation on newer Omarchy hosts whose
plugin API keeps first-party service objects private.

- Now Playing falls back to Quickshell's shared MPRIS discovery when Omarchy's
  media service is unavailable to plugins. Actions still target the displayed
  player and respect its capabilities; no watcher process or new daemon is added.
- Optional native touch can use a synchronous boolean guard from the enabled
  user-owned lock clone. The lock object and authentication context stay private.
  Input stops at lock request and provider loss; cancelled touches cannot replay
  after unlock. Conflicting guard publishers deny native routing.
- If no synchronous guard is available, native device ownership is released and
  Hyprland manages touch and lock-screen routing. Reconnect cannot override this.
- Diagnostics report the routing mode, host guard, and whether interaction is
  allowed. Documentation distinguishes compositor touch from independent native
  touch during captured gameplay.

## Updating

Standard mode requires no compilation:

```bash
omarchy plugin update pretty.omadeck
```

If using native integration, rebuild it after the update and reload the shell:

```bash
~/.config/omarchy/plugins/pretty.omadeck/scripts/build-native
omarchy restart shell
```

On hosts with a private lock service, follow the optional
[host input guard instructions](../../integrations/omarchy/README.md) for native
touch independent of game mouse capture. Keep the actual touchscreen enabled
and mapped to the deck in Hyprland, disabling only its separate mouse-emulation
endpoint, so compositor fallback remains usable. OmaDeck does not automatically
edit the lock plugin or compositor configuration.

Existing preferences retain their formats. Rollback requires the prior source
and matching rebuilt native artifacts; keep the user-owned lock integration
and compositor mapping consistent with the selected routing mode.
