# OmaDeck v0.8.0-rc.1 — Preferences, installation, and reliability

This prerelease gathers all changes since v0.7.2, including features already
merged into `main` and subsequent reliability work. Real touchscreen/lock,
device reconnect, suspend/resume, and clean-session installation acceptance
remain pending. It is not the stable release.

## Preferences and everyday controls

- A unified Preferences hub brings OmaDeck controls and Omarchy settings
  handoffs together, including appearance, displays, input, sound, networking,
  applications, power, and advanced tools.
- Choose the deck display and primary workspace monitor from connected screens.
  When optional native touch is available, choose a detected direct touchscreen.
  Selections persist and failed saves remain visible.
- Timer setup uses touch-sized duration fields and step buttons, responsive
  controls, and a sound selector. Starting a timer returns the companion card
  to Weather while progress remains visible in the Clock.
- Clock/Weather presentation and drawer/overlay interactions have been refined
  for the deck's constrained geometry. Long-press layout editing no longer also
  opens the timer.

## Installation

- Standard mode runs through Omarchy's normal plugin add/enable path without
  compiling native components. It uses compositor-managed touch.
- The direct touch bridge and system-tray controller remain optional. Their
  build now creates, tests, and verifies both artifacts from a clean checkout.
- Development checkout instructions live in CONTRIBUTING.md. The README retains
  standard installation and optional native-build instructions.
- Marketplace standard-install availability is a separate maintainer-controlled
  setting. The existing request is linked in docs/MARKETPLACE.md.

## Reliability and recovery

- Now Playing transport targets the displayed MPRIS player, checks its current
  capabilities, and refuses stale player identities. Seeking reconciles with
  the real player after rejected/external seeks and track changes.
- Clipboard actions retain complete content behind bounded previews and detect
  stale history entries. Failed copy launches clean up correctly.
- Layout and application-list save failures remain visible with retry. Hardware,
  appearance, timer, and timer-sound settings recover from failed writes; choosing
  an already-saved option does not report a false failure.
- The deck resolves Omarchy's enabled lock implementation, including user clones,
  and blocks interaction while locked or unresolved. Native touch contacts
  cancelled while disabled cannot resume as clicks after re-enabling.
- System monitoring and audio-output resolution pause when their drawers close.
  System failures retain the last good snapshot with age and retry feedback.
  Helpers have bounded output and deadlines; late audio-output results are
  discarded after device changes.

## Validation

The release candidate is checked by `scripts/check`, including real offscreen
Quickshell fixtures, private D-Bus media players, and a clean native build with
three CTest targets. Release evidence is recorded in docs/RELEASE_CHECKLIST.md;
hosted CI is linked from the release's commit/PR.

Coverage includes settings upgrade/rollback against the published snapshot,
read-only storage and recovery, 100 media appearance/removal and card-recreation
cycles with descriptor checks, rapid output changes, oversized responses, and
termination-resistant helpers. These tests do not replace hardware acceptance.

## Installing and upgrading

The README's one-line install command follows the default branch, `main`; it
will not select this prerelease while the candidate remains on its release
branch. The exact candidate is available from this release tag for isolated
review and testing. Do not mistake the current marketplace snapshot for this
candidate.

Existing preferences keep their current JSON formats. If using optional native
integration, rebuild its artifacts for the installed source and Qt/Quickshell
versions before loading them. Rollback requires restoring the prior source and
matching native artifacts; preserve a copy of settings before live testing.

## Known limits

- Now Playing discovers players that expose MPRIS through Omarchy. It does not
  identify arbitrary PC audio from applications that expose no media metadata.
- Standard touch may need compositor mapping on different hardware. Native touch
  is optional and still needs real lock/reconnect/suspend acceptance.
- Audio scope remains volume, mute, and aggregate mixing. EQ, DSP presets,
  universal media detection, and additional service integrations are not added.
